# JefroCrypto Threads Engine v0.4.1 · Style Intelligence + Apify

Главная цель: **Research Engine → Style Lab → AI Writer → модерация → Threads → аналитика**.
Основной язык: русский. Никаких гарантий вирусности/конверсий.

## Новое в v0.4.0

- **Style Lab** в Growth Studio: библиотека механик из собранных чужих публикаций с привязкой к исходному посту и автору.
- Автоматическая эвристическая разметка: тип хука, тон, структура, эмоциональный триггер, длина первого предложения, вопросы, абзацы.
- Кнопка **AI-разбор 5 постов** для глубокого анализа приёмов через настроенный Gemini/OpenRouter (расходует AI-запросы, запуск вручную).
- Подбор паттернов под тему по словарному пересечению и языку, разнообразию типов и авторов. Относительные просмотры отображаются только при минимум трёх доступных измерениях у одного автора. Это наблюдательная статистика, а не прогноз эффективности.
- Генерация с использованием **абстрактных стилистических правил**. Исходные чужие тексты не передаются в Writer для копирования. Ручное одобрение перед публикацией обязательно.
- Можно отключить любой паттерн. Кнопка «Обновить из Research» идемпотентна.
- Сохранились существующие: Meta OAuth, публичные юридические страницы, ручное редактирование и публикация, партнерки, переходы, Research, импорт JSON/CSV.

## Как попробовать Style Lab

1. В `/research` → Data & Jobs импортируй чужие публикации (с автором, текстом и источником). Старый поиск по словам и мониторинг работают при разрешениях Meta; v0.4.0 **не обходит ограничения Meta**.
2. Вернись на главную → Style Lab → **Обновить из Research**.
3. Нажми **AI-разбор 5 постов** при наличии ключа Gemini/OpenRouter, если нужна более глубокая стилистическая разметка.
4. Введи тему, нажми **Подобрать под тему**. Можно снять галочки с неудачных паттернов.
5. В панели генерации включи «Использовать изученные паттерны», выбери стиль и смелость подачи, создай варианты. Сначала проверь их вручную, затем одобри.
6. После публикации заполняй просмотры/регистрации; клики учитываются при настройке `PUBLIC_BASE_URL` и использовании ссылок /go/. Сравнивай собственные результаты с учётом размера выборки.

## Обновление с v0.3.3 (Render)

Перед обновлением **сделай резервную копию PostgreSQL/SQLite**. Архив не содержит `.env` и настоящую БД.

1. Замени файлы проекта на GitHub файлами архива (не загружай `.env`, дампы и секреты).
2. Текущие переменные Render **не удаляй**. Обновление не требует новых обязательных ключей.
3. Если используешь Alembic, выполни `python -m alembic upgrade head`. В обычном запуске `init_db()` также создаст новую таблицу `style_patterns`, не затрагивая существующие записи.
4. Render → Manual Deploy → Deploy latest commit.
5. Проверь `/healthz`, `/api/health` (с админ-авторизацией, `version: 0.4.0`), UI → Style Lab.
6. На Render Free SQLite в контейнере **непостоянна**. Используй внешнюю PostgreSQL с `DATABASE_URL` для черновиков и исследований; без неё не накапливай важные данные.

## Возможности / ограничения

- «Обучение» здесь означает **RAG-подбор и структурированную память приёмов**, а не fine-tuning модели и не автоматическое улучшение её весов.
- Без одобрения `threads_keyword_search` и `threads_profile_discovery` официальный Threads API не будет автоматически собирать чужие публикации. Доступен ручной импорт.
- Данные просмотров чужих постов могут отсутствовать; не подменяются выдуманными значениями. Поиск исходных публикаций сохраняет ссылки в Research.
- Качественные механики могут не приводить к кликам. Нужны тесты на собственных постах и достаточные выборки.
- AI-разбор отправляет текст исследуемых публикаций выбранному AI-провайдеру; не загружай приватные данные без прав.
- Рекламные ссылки требуют прозрачного указания заинтересованности. Не заявляй необоснованные преимущества, доходность и эксклюзивные скидки.

## Быстрый запуск на Windows (PowerShell)

1. Распакуй ZIP в **новую папку**. Для сохранения старой истории скопируй **свой** `threads_engine.db` из старого проекта, если работал с SQLite. Убедись, что старый процесс остановлен; лучше скопировать файл вместе с его согласованной резервной копией, а не при работающем сервере. Если использовался внешний PostgreSQL, просто сохрани `DATABASE_URL`.
2. В корне новой папки выполни команды:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

3. Заполни в `.env` хотя бы `ADMIN_PASSWORD` и один из `GEMINI_API_KEY` или `OPENROUTER_API_KEY`. Для публикации нужен `THREADS_ACCESS_TOKEN`. В PowerShell нет необходимости активировать `.venv`: команды ниже работают и при запрете `Activate.ps1`.
4. Перед обновлением старой SQLite **сделай резервную копию** (этот скрипт использует безопасный SQLite backup API). Если база PostgreSQL, используй `pg_dump` или бэкапы провайдера. Затем выполни миграцию:

```powershell
.\.venv\Scripts\python.exe tools/backup_sqlite.py
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

5. Открой `http://127.0.0.1:8000` и войди под `ADMIN_USERNAME` / `ADMIN_PASSWORD`. Исследования остались на `http://127.0.0.1:8000/research`.

API status: `GET /api/health` с Basic-авторизацией; доступный хостингу ливнес `GET /healthz` возвращает только `ok`.

## Генерация постов и клики

Новый Writer использует одну AI-генерацию для получения 5 хуков и 3 текстов. Каждый текст проверяется на длину (не более 500 символов), получает тип хука и редакторскую оценку, сохраняется как `pending_review`. Одобрение, правка, отклонение и публикация работают в правой колонке. Ссылку и дисклеймер приложение добавляет само, независимо от генерации AI.

**Для учёта переходов необходим публичный HTTPS-адрес**. В `.env` укажи, например:

```env
PUBLIC_BASE_URL=https://jefrocrypto-threads-engine.onrender.com
BASE_REFERRAL_URL=https://fomo.family/r/jefrocrypto
DEFAULT_POST_LANGUAGE=ru
```

Тогда в посте появится короткий адрес вида `https://.../go/fomo?c=15&v=1`. По переходу сервер запишет событие (время, пост и оффер; **без IP, cookies, браузерного fingerprint**) и перенаправит на точную реферальную ссылку FOMO, не дописывая туда новые `ref`/UTM-параметры. Ссылка будет доступна даже без логина администратора. Предварительные просмотры ссылок известными ботами не считаются, но остальные автоматические обращения могут влиять на счётчик. Счётчик — это HTTP-переходы, **не уникальные люди и не регистрации**.

**При отсутствии PUBLIC_BASE_URL** будут использованы прямые партнёрские ссылки. Посты работают, но переходы по ним в программе не считаются. Сначала настрой домен, потом генерируй тексты, если нужна точная атрибуция по вариантам. Проверь, разрешает ли партнёрская программа промежуточные редиректы и корректно ли после перехода начисляются реферальные регистрации. Для раскрытия рекламы приложение добавляет `Партнёрская ссылка. Могу получить комиссию.`

Внизу интерфейса нажми **Внести** для просмотров/регистраций/дохода, которые ты получил из статистики Threads и партнёрского кабинета. Не оставляй результат в качестве «0», если данных пока нет: пустое поле означает неизвестно. CTR = переходы / просмотры; показатель регистрации/клик не показывается, если регистраций больше, чем зарегистрированных переходов.

## Публикация и безопасность

- По умолчанию `AUTO_PUBLISH_ENABLED=false`, а `AUTO_PUBLISH_REQUIRE_APPROVAL=true`. Пост без твоего одобрения не публикуется.
- Перед отправкой статус атомарно меняется на `publishing`. Повторная отправка заблокирована. Если ответ от Threads не получен и неизвестно, был ли пост опубликован, ставится `publish_uncertain`. **Сначала вручную проверь Threads**, лишь после этого используй кнопку сброса.
- После публикации пост нельзя отредактировать через Writer.
- Реакции Threads зависят от разрешений токена и Meta API; без прав публикация вернёт ошибку.
- В ZIP **нет** `.env`, приватных ключей, токенов, `.db`, старых логов, `cloudflared.exe` и `.venv`. Исходный архив содержал секреты, так что **замени старые API-ключи/токены и пароль**, если архив хоть где-то мог быть доступен другим.
- OAuth на Render: укажи `THREADS_APP_ID`, `THREADS_APP_SECRET`, `THREADS_REDIRECT_URI` и перейди **из того же браузера** на `https://<твой-домен>/auth/threads/start`. Сервис создаст одноразовый `state`, запишет безопасную временную cookie и перенаправит на Meta. Переменная `THREADS_OAUTH_STATE` больше не нужна для этого сценария; она остаётся только для совместимости со старым ручным запуском `tools/refresh_threads_token.py url`. При возврате скопируй одноразовый `code` и выполни локально `... exchange "<CODE>"`, затем перенеси итоговый `THREADS_ACCESS_TOKEN` в Render Environment. Callback не логирует OAuth code и проверяет `state`.
- `/static` публично отдаёт только файлы интерфейса без данных; API и сами черновики требуют Basic auth. На публичном хостинге используй HTTPS и надёжный пароль.

## Render Free (важно для данных)

`render.yaml` создаёт **один бесплатный web-service** без платного Render PostgreSQL. Деплой через репозиторий GitHub или через Render Blueprint. В Render Environment Variables добавь:

```env
ADMIN_PASSWORD=<длинный-уникальный-пароль>
OPENROUTER_API_KEY=<ключ-или-GEMINI_API_KEY>
DATABASE_URL=<postgresql-connection-url-постоянной-внешней-базы>
PUBLIC_BASE_URL=https://<твой-домен-на-render>
THREADS_ACCESS_TOKEN=<при-готовности-публикации>
```

Если `DATABASE_URL` **не задан**, приложение использует SQLite внутри контейнера. На Render Free это **временное хранилище**, которое может потеряться при пересборке/перезапуске. Для реального ведения аккаунта обязательно подключи постоянную внешнюю PostgreSQL и держи бэкапы. Бесплатные инстансы могут засыпать, поэтому фоновые расписания и авто-публикация по умолчанию выключены в `render.yaml`. Для непрерывных задач нужен хостинг/worker, который не засыпает. `PUBLIC_BASE_URL` должен точно соответствовать адресу приложения, без завершающего `/`.

Для переноса данных SQLite → PostgreSQL недостаточно поменять `DATABASE_URL`. Сначала нужно экспортировать и импортировать записи отдельно. Скрипт автоматического переноса между разными движками БД в этой версии не реализован. **Не удаляй исходную SQLite, пока не проверишь новую БД.**

## Research: поиск чужих постов в Threads (v0.3.1)

В Research теперь по умолчанию выбран **«Поиск по чужим постам»**, а не «Все источники».
В фильтрах есть «Только чужие посты»; чтобы скрыть ранее найденные собственные публикации, добавь в `.env`:

```env
THREADS_OWN_USERNAME=твой_ник_в_threads
```

Для автоматического поиска публикаций **других аккаунтов** нужен одобренный Meta App Review **Advanced Access** для `threads_keyword_search`, а не только включённое разрешение в настройках приложения. Затем повторно авторизуй Threads, чтобы получить токен с этим доступом, и поставь `THREADS_KEYWORD_SEARCH_ENABLED=true`. Без App Review Meta часто возвращает только твои посты с кодом 200. Код теперь распознаёт такой случай и отмечает задачу как `skipped` вместо ложного `success`. Если /me недоступен, укажи `THREADS_OWN_USERNAME` вручную.

**Пока нет App Review:** в Threads выбери интересные публичные публикации, скопируй их текст, ссылку и имя автора, затем добавь через Research → Data & Jobs → «Ручное добавление публикации», либо импортируй CSV/JSON. Одного username для автоматического мониторинга недостаточно без отдельного одобренного `threads_profile_discovery`. Добавление автора в Data & Jobs не выдаёт новых прав доступа.

Обновление не удаляет старые данные и не требует миграции БД.

## v0.4.1: чужие посты без Advanced Access Meta (Apify)

**Официальный Threads API по-прежнему используется для публикации на своём аккаунте.** Для исследования чужих публичных постов добавлен независимый адаптер `ApifyThreadsSource` для [agenttoolworks/threads-scraper](https://apify.com/agenttoolworks/threads-scraper). Это сторонний сервис, а не официальный API Meta. Проверяйте условия Meta, Apify и поставщика данных перед применением. Доступность публичных данных может измениться.

### Настройка Render

1. Создайте аккаунт [Apify](https://console.apify.com/) и протестируйте Actor на малом объёме. Для получения API-токена откройте Settings → API & Integrations. Возможны расходы; сначала ознакомьтесь с текущими тарифами и выставьте бюджет/лимит в Apify.
2. В Render → Web Service → Environment добавьте `APIFY_TOKEN` (не в GitHub!). Укажите `APIFY_MAX_ITEMS=20` и проверьте, что `RESEARCH_ENABLED_SOURCES` содержит `apify_threads`. Если переменная не задана, используется штатный список, уже включающий `apify_threads`.
3. Нажмите Save, deploy и откройте `/research` → Overview → тип **Поиск чужих постов (Apify)**. Введите 1–3 запроса, например `мемкоины, defi, solana`, нажмите «Запустить в фоне».
4. Для выбранных авторов используйте тип **Посты выбранных авторов (Apify)** и поле «Аккаунты» (username через запятую, без `@`).
5. Проверьте Data & Jobs: `apify_search` или `apify_profiles`. Новые публикации появятся в Trending Posts, затем запустите анализ Style Lab и генерацию AI Writer.

### Ограничения и стоимость

- Поиск ограничен тремя ключевыми фразами за один запуск, пятью аккаунтами и `APIFY_MAX_ITEMS` (максимум 50) на один запрос. **Это лимит строк, не денежный лимит**. Дополнительно установите расходный лимит в Apify. Для автоматического Apify-сбора расписание не включено: запуск только вручную.
- Actor по заявлению автора возвращает приблизительно первые 20 публичных результатов на запрос. Просмотры чужих постов недоступны: `views=null`. Остальные метрики могут быть неполными. Собственные публикации фильтруются по `THREADS_OWN_USERNAME`.
- Если внешний Actor работает дольше ответа API, результат может быть недоступен в приложении. Проверьте статус в Apify Console. **Не запускайте повторно до проверки**, чтобы избежать дублирующих расходов.
- API-токен хранится только на сервере, в заголовке Authorization, не передаётся в браузер и не сохраняется в базе.
- Библиотека стилей извлекает приёмы и структуры, не копирует тексты других авторов. Для заработка на реферальных продуктах сохраняйте прозрачные рекламные пометки.

### Дополнительно: бесплатно без стороннего API

Оставлен импорт JSON/CSV через Research → Data & Jobs. Он работает даже без токенов Meta/Apify. Если сервис Apify окажется недоступен или не подходит по условиям, можно использовать этот способ.
