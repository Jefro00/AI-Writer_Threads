# JefroCrypto Threads Engine v0.3.1 · Growth Studio

Генератор криптопостов с сильными хуками, ручной модерацией, реферальными офферами и прозрачной аналитикой. **Основной язык: русский**. Английский можно выбрать в интерфейсе. Основная реферальная ссылка в новой установке: `https://fomo.family/r/jefrocrypto`.

**Это обновление архива v0.2, а не новый пустой проект.** Сохранены Research Engine, Writer-бривы, отчёты, текущие эндпоинты и публикация в Threads. Стандартная команда `/api/generate` работает как раньше, но теперь использует русский по умолчанию. Новые функции доступны в `/api/growth/*` и на главной `/`.

## Быстрый запуск на Windows (PowerShell)

1. Распакуй ZIP в **новую папку**. Для сохранения старой истории скопируй **свой** `threads_engine.db` из старого проекта, если работал с SQLite. Убедись, что старый процесс остановлен; лучше скопировать файл вместе с его согласованной резервной копией, а не при работающем сервере. Если использовался внешний PostgreSQL, просто сохрани `DATABASE_URL`.
2. В корне новой папки выполни команды:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

3. Заполни в `.env` хотя бы `ADMIN_PASSWORD` и один из `GEMINI_API_KEY` или `OPENROUTER_API_KEY`. Для публикации нужен `THREADS_ACCESS_TOKEN`. В PowerShell нет необходимости активировать `.venv`: команды ниже работают и при запрете `Activate.ps1`.
4. Перед обновлением старой SQLite **сделай резервную копию** (этот скрипт использует безопасный SQLite backup API). Если база PostgreSQL, используй `pg_dump` или бэкапы провайдера. Затем выполни миграцию:

```powershell
.\.venv\Scripts\python.exe tools/backup_sqlite.py
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

5. Открой `http://127.0.0.1:8000` и войди под `ADMIN_USERNAME` / `ADMIN_PASSWORD`. Исследования остались на `http://127.0.0.1:8000/research`.

API status: `GET /api/health` с Basic-авторизацией; доступный хостингу ливнес `GET /healthz` возвращает только `ok`.

## Генерация постов и клики

Новый Writer использует одну AI-генерацию для получения 5 хуков и 3 текстов. Каждый текст проверяется на длину (не более 500 символов), получает тип хука и редакторскую оценку, сохраняется как `pending_review`. Одобрение, правка, отклонение и публикация работают в правой колонке. Ссылку и дисклеймер приложение добавляет само, независимо от генерации AI.

**Для учёта переходов необходим публичный HTTPS-адрес**. В `.env` укажи, например:

```env
PUBLIC_BASE_URL=https://jefrocrypto-threads-engine.onrender.com
BASE_REFERRAL_URL=https://fomo.family/r/jefrocrypto
DEFAULT_POST_LANGUAGE=ru
```

Тогда в посте появится короткий адрес вида `https://.../go/fomo?c=15&v=1`. По переходу сервер запишет событие (время, пост и оффер; **без IP, cookies, браузерного fingerprint**) и перенаправит на точную реферальную ссылку FOMO, не дописывая туда новые `ref`/UTM-параметры. Ссылка будет доступна даже без логина администратора. Предварительные просмотры ссылок известными ботами не считаются, но остальные автоматические обращения могут влиять на счётчик. Счётчик — это HTTP-переходы, **не уникальные люди и не регистрации**.

**При отсутствии PUBLIC_BASE_URL** будут использованы прямые партнёрские ссылки. Посты работают, но переходы по ним в программе не считаются. Сначала настрой домен, потом генерируй тексты, если нужна точная атрибуция по вариантам. Проверь, разрешает ли партнёрская программа промежуточные редиректы и корректно ли после перехода начисляются реферальные регистрации. Для раскрытия рекламы приложение добавляет `Партнёрская ссылка. Могу получить комиссию.`

Внизу интерфейса нажми **Внести** для просмотров/регистраций/дохода, которые ты получил из статистики Threads и партнёрского кабинета. Не оставляй результат в качестве «0», если данных пока нет: пустое поле означает неизвестно. CTR = переходы / просмотры; показатель регистрации/клик не показывается, если регистраций больше, чем зарегистрированных переходов.

## Несколько партнёрских программ

В левой колонке открой **Добавить или изменить партнёрку** и введи короткое имя, HTTPS-рефку и достоверное описание. Выбери оффер в форме генерации. Система не проверяет автоматически маркетинговые заявления: указывай только информацию, которую можешь подтвердить.

## Публикация и безопасность

- По умолчанию `AUTO_PUBLISH_ENABLED=false`, а `AUTO_PUBLISH_REQUIRE_APPROVAL=true`. Пост без твоего одобрения не публикуется.
- Перед отправкой статус атомарно меняется на `publishing`. Повторная отправка заблокирована. Если ответ от Threads не получен и неизвестно, был ли пост опубликован, ставится `publish_uncertain`. **Сначала вручную проверь Threads**, лишь после этого используй кнопку сброса.
- После публикации пост нельзя отредактировать через Writer.
- Реакции Threads зависят от разрешений токена и Meta API; без прав публикация вернёт ошибку.
- В ZIP **нет** `.env`, приватных ключей, токенов, `.db`, старых логов, `cloudflared.exe` и `.venv`. Исходный архив содержал секреты, так что **замени старые API-ключи/токены и пароль**, если архив хоть где-то мог быть доступен другим.
- OAuth: для генерации URL и callback установи `THREADS_APP_ID`, `THREADS_APP_SECRET`, `THREADS_REDIRECT_URI` и **`THREADS_OAUTH_STATE`**, случайную строку от `python -c "import secrets;print(secrets.token_urlsafe(32))"`. Дальше: `python tools/refresh_threads_token.py url`, авторизация, `... exchange "<CODE>"`. Callback не логирует OAuth code и проверяет `state`.
- `/static` публично отдаёт только файлы интерфейса без данных; API и сами черновики требуют Basic auth. На публичном хостинге используй HTTPS и надёжный пароль.

## Render Free (важно для данных)

`render.yaml` создаёт **один бесплатный web-service** без платного Render PostgreSQL. Деплой через репозиторий GitHub или через Render Blueprint. В Render Environment Variables добавь:

```env
ADMIN_PASSWORD=<длинный-уникальный-пароль>
OPENROUTER_API_KEY=<ключ-или-GEMINI_API_KEY>
DATABASE_URL=<postgresql-connection-url-постоянной-внешней-базы>
PUBLIC_BASE_URL=https://<твой-домен-на-render>
THREADS_ACCESS_TOKEN=<при-готовности-публикации>
```

Если `DATABASE_URL` **не задан**, приложение использует SQLite внутри контейнера. На Render Free это **временное хранилище**, которое может потеряться при пересборке/перезапуске. Для реального ведения аккаунта обязательно подключи постоянную внешнюю PostgreSQL и держи бэкапы. Бесплатные инстансы могут засыпать, поэтому фоновые расписания и авто-публикация по умолчанию выключены в `render.yaml`. Для непрерывных задач нужен хостинг/worker, который не засыпает. `PUBLIC_BASE_URL` должен точно соответствовать адресу приложения, без завершающего `/`.

Для переноса данных SQLite → PostgreSQL недостаточно поменять `DATABASE_URL`. Сначала нужно экспортировать и импортировать записи отдельно. Скрипт автоматического переноса между разными движками БД в этой версии не реализован. **Не удаляй исходную SQLite, пока не проверишь новую БД.**

## Research: поиск чужих постов в Threads (v0.3.1)

В Research теперь по умолчанию выбран **«Поиск по чужим постам»**, а не «Все источники».
В фильтрах есть «Только чужие посты»; чтобы скрыть ранее найденные собственные публикации, добавь в `.env`:

```env
THREADS_OWN_USERNAME=твой_ник_в_threads
```

Для автоматического поиска публикаций **других аккаунтов** нужен одобренный Meta App Review **Advanced Access** для `threads_keyword_search`, а не только включённое разрешение в настройках приложения. Затем повторно авторизуй Threads, чтобы получить токен с этим доступом, и поставь `THREADS_KEYWORD_SEARCH_ENABLED=true`. Без App Review Meta часто возвращает только твои посты с кодом 200. Код теперь распознаёт такой случай и отмечает задачу как `skipped` вместо ложного `success`. Если /me недоступен, укажи `THREADS_OWN_USERNAME` вручную.

**Пока нет App Review:** в Threads выбери интересные публичные публикации, скопируй их текст, ссылку и имя автора, затем добавь через Research → Data & Jobs → «Ручное добавление публикации», либо импортируй CSV/JSON. Одного username для автоматического мониторинга недостаточно без отдельного одобренного `threads_profile_discovery`. Добавление автора в Data & Jobs не выдаёт новых прав доступа.

Обновление не удаляет старые данные и не требует миграции БД.
